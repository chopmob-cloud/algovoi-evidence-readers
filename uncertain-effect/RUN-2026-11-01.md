## The outside audit, and what it says about the first figure

An independent audit of the first version (separate container, its own stage,
its own probes) made two findings that matter more than the figure.

**The first version was a clone.** A differential fuzz of 4,000 randomly
generated records compared the reader against the corpus's own reference reader
on the first-failing answer and found **no divergence at all**. So "a second
implementation agrees 27 of 27" was evidence of transcription, not of independent
implementability, and the first record did not say so. That is the sharpest
statement available about this kind of run: a green differential figure can mean
the two implementations were written by two people, or it can mean one was
written from the other, and the corpus cannot tell you which.

**Four shapes failed open.** Each is a shape the 27 cases never build:

| Shape | First version | Now | Shared with the reference reader? |
| --- | --- | --- | --- |
| `reported` absent, null or empty | allow | deny `outcome_disagrees_with_authority` | no, the reference raises |
| `ownerEffects` is `"1"`, `true`, `1.0` or absent | `true` allowed | deny `duplicate_effect` | no, the reference raises |
| cover for a resend from an owner answer about another idempotency key | allow | deny `retry_after_unknown` | yes |
| a dispatch carrying a worker or fencing token with no `leases` record | allow | deny `dispatch_beyond_lease` | yes |

The last two are the interesting ones: the reference reader has the same hole,
so the corpus cannot contain a case that catches it, and a reader written
faithfully from the reference reproduces it. Those are reported as a gap in the
corpus, not only as a fix here.

`check_audit_probes.py` pins all four, each with a control that must still be
allowed, so a reader that simply refuses everything fails the script. It runs as
part of `run.sh`; 18 of 18 probes hold, including one that pins the dispatch
asymmetry rather than leaving it to a comment.

After the fixes the same fuzz over 4,000 records shows 57 records in 11
divergence classes. Ten classes are this reader refusing where the reference
allows, or naming an earlier check than the reference names. One class, 3
records, is this reader allowing where the reference refuses, and it is the
wrong-key reading in the other direction: the reference attributes an owner
answer about another key to this operation and calls the effect committed, we
ignore it and settle unknown. The corpus has no case that settles which is
right, which is why it is recorded here rather than decided silently.

## The second review, and one finding it got wrong

An independent second-model review of the commits (verdict FINDINGS, exit 1)
raised four findings, none of them BLOCKER or HIGH. Each was checked against the code
before acting, and one was rejected:

| Finding | Disposition |
| --- | --- |
| MEDIUM: `worker: null` counted as a lease claim, so a dispatch that claims nothing is denied | **adopted**. The check now requires a non-null value, with a control probe that must still be allowed. |
| MEDIUM: the probe labelled "count absent" set `null` instead of removing the key | **adopted**. A second probe removes the key. |
| MEDIUM: attribution returns false for every item when the operation names no key, so a record whose only evidence is an owner answer loses it | **not reachable in the decision path**: the identity check refuses such a record before any check that reads the settled outcome. Pinned instead of argued: the probe `operation names no key` requires `operation_identity_missing`, so the ordering that makes it unreachable is now tested. |
| MEDIUM: a confirmed dispatch under another key still settles `committed`, unlike an off-key owner answer | **rejected, with the reason recorded.** The corpus's own retained declaration settles `committed` for both cases that build the shape (`identity-missing-key` and `retry-under-new-key`, both `committed`), and both are denied on an earlier check, so the reading changes no decision. Applying the reviewer's fix made the derived outcomes disagree with that declaration on two cases while leaving every decision identical, which `report_axes.py` reported as `2 disagreements`. The asymmetry between answers and dispatches is now written into the reader's docstring as a decision, not a slip. |

The gate is worth having for the two LOW items and for the probe-quality point:
a probe whose label claims one shape and whose body builds another is the failure
this whole record exists to avoid, and it was in the script written to catch that
class of failure. It also had to be retried several times before it produced anything: two free
endpoints answered 504 and then hung, so the reviews came from a paid fallback The second run, on the commit that acted on the first, found two LOW
items in the probe script only: a comment that still asserted the dispatch
behaviour the first review's rejected finding asked for, and a `pop` that would
raise `KeyError` rather than fail an assertion if the record builder changed.
Both were fixed, and the asymmetry the comment described is now a probe with its
reason attached, so the next person to "fix" it is sent back to the corpus's
declaration instead of to the code.

The third pass found one MEDIUM: that the new asymmetry probe would pass even if
the reader never settled a confirmed dispatch at all, so it pins only
non-refusal. That claim is testable, so it was tested rather than argued. Two
mutants of the reader were run against the probe script:

| Mutant | Probe result |
| --- | --- |
| confirmed dispatches require matching idempotency keys (the rejected fix) | probe **fails**, `deny/outcome_disagrees_with_authority` where `allow/effect_held` is required |
| the confirmed-dispatch clause removed entirely | probe **fails**, for the same reason, plus the cover control |

So the probe does fail when either reading it is meant to exclude is installed,
and the finding was rejected on that evidence. A mutant that settles `committed`
unconditionally would pass it, and would also fail most of the corpus and the
cover controls, so the probe's power is bounded but not empty.

Across three completed reviews the gate raised seven findings: four were acted
on, one was converted into a probe because the code path it described is already
refused earlier, and two were rejected after testing, both with the test
recorded here.

## What this record does not prove

- It is a **directed** run. The reader's author had read the corpus's reference
  reader before writing it, and the differential fuzz in the audit section above
  found the first version indistinguishable from that reference on 4,000 random
  records. The figure shows the stated checks are implementable by a second pair
  of hands; it does not show the text is determinate from a cold start. A blind
  result would need a reader written by someone who had read only the corpus
  README, and a differential fuzz against the reference run afterwards to show
  the two are not the same code.
- Nothing about the AlgoVoi offline verifier's signature, request-binding,
  effect-binding or amount axes. A trail record has nothing for them to read.
- Nothing about any producer's truthfulness, the owner ledger's correctness,
  clock agreement, or operations the record does not list.
- Nothing about `request-effect-join-fixture/v1`. That contract is a different
  format with a different question, and this reader does not read it.
